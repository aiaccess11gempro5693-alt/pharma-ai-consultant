## Хендовер: AI-консультант по продукту для фармы и БАД

Sep 29, 2026 · @Oleg Zhakov

### 1. Суть и принципы

Мы делаем чат-консультанта по продукту фармкомпании или бренда БАД, который отвечает только согласованными формулировками. Одна база знаний обслуживает четыре аудитории: покупателя, фармацевта, врача и медицинского представителя.

Принятые решения:

- **Согласуем не ответы, а атомы.** Атом — одно проверенное утверждение с ID (доза, противопоказание, условие хранения). Юристы и медотдел утверждают список атомов, а не сотни готовых ответов.
- **Бот не может сказать ничего нового.** Любой факт, цифра или обещание в ответе берётся из атома. Всё остальное — связки и служебные фразы без фактов.
- **Одна база, четыре голоса.** Аудитории пересекаются на 60–70%, различаются глубина, тон и доступ. Это теги на атомах, а не четыре бота.
- **Контроль архитектурный.** Последняя проверка — детерминированное правило, а не нейросеть. Непонятный вопрос ведёт к безопасной служебной фразе, а не к импровизации.
- **Первый продукт строит фундамент.** Каждый следующий продукт добавляет только дельту новых атомов.
- **Стартуем с линейки «Контроль»** (ответ собирается скриптом из базы), «Живой диалог» — апгрейд после пилота.

### 2. Архитектура

Есть две линейки на одной базе атомов. Продаём и запускаем первой «Контроль».

|  | «Контроль» | «Живой диалог» |
|---|---|---|
| Кто пишет текст ответа | Скрипт склеивает атомы и связки | Нейросеть формулирует из отобранных атомов |
| Роль нейросети | Только классификация вопроса | Классификация, генерация, проверка |
| Предсказуемость | 100%: все возможные тексты заранее видны юристам | Высокая, держится на верификаторе |
| Составные вопросы | Работают, но звучат механичнее | Звучат естественно |
| Токены на сообщение | Сотни, копейки | ~5 тыс., 1–3 ₽ на российских моделях |
| Когда продавать | Пилот, консервативная фарма | Апгрейд, когда логи показывают сухость |

**Путь сообщения в «Контроле»:**

- **Фильтры.** Жалоба на самочувствие → служебный ответ + передача в отдел качества. Вопрос не о продукте или провокация → служебный ответ.
- **Классификатор.** Определяет аудиторию, одно или несколько намерений и уверенность.
- **Порог уверенности.** Ниже порога → служебная фраза («уточните вопрос» или «обратитесь к специалисту»).
- **Выборка атомов** по намерениям с фильтром по аудитории.
- **Сборка по правилам:** стилевые фразы по ситуации + атомы целыми предложениями + связки между предложениями + обязательные пометки.
- **Отправка и запись в журнал** (вопрос, намерения, ID атомов, уверенность).

**В «Живом диалоге»** шаг 5 заменяется генерацией: модель получает 3–10 атомов, пишет ответ со ссылкой на ID после каждого предложения, возвращает JSON (sentences[{text, atom_ids}], status: answer|fallback). Затем второй проход проверяет, что нет утверждений вне атомов, и детерминированные правила сверяют цифры, ID и стоп-слова. Не прошло → служебная фраза. Настройки: temperature 0, structured output, 5–8 примеров в промпте, включая примеры правильного отказа.

### 3. Модель данных

В базе три типа записей: атомы (факты), стилевой слой (без фактов) и служебные ответы. Атомы лежат на четырёх уровнях переиспользования.

**Типы записей:**

| Тип | Что содержит | Кто согласует | Пример |
|---|---|---|---|
| Атом | Одно фактическое утверждение, целым предложением | Юристы + медотдел, по каждому продукту | «Взрослым по 1 капсуле в день во время приёма пищи» |
| Стилевая фраза | Эмпатия, связка, переход, уточнение, завершение; ноль фактов | Один раз на бренд | «Что касается приёма, …» |
| Служебный ответ | Отказ, перевод к врачу, уточнение, реакция на жалобу | Один раз на бренд | «С вопросом о лечении лучше обратиться к врачу» |

**Поля атома:** ID · уровень (бренд / ингредиент / продукт) · раздел (состав, приём, противопоказания, хранение…) · аудитории · точный текст · источник (этикетка, СГР, ОХЛП, материалы бренда) · версия · статус (черновик / на согласовании / утверждён / устарел) · дата утверждения.

**Правила текста атомов:** цифры, дозы и противопоказания — буквально по источнику, без пересказа. Атом — законченное предложение, чтобы скрипт не склеивал слова внутри фразы. Одна мысль на атом.

**Уровни переиспользования:**

- **Инфраструктура** — код, классификатор, админка, журнал. Один раз на все клиенты.
- **Бренд** — стилевой слой, служебные ответы, стоп-лист, общие атомы (технология, стандарты качества, «без глютена, сахара, ГМО», контакты). Один раз на клиента.
- **Ингредиент** — описания веществ и форм (пиперин, метилкобаламин, пиколинат цинка). Переиспользуются между продуктами, если юристы подтвердят универсальность формулировки.
- **Продукт** — дозировки, состав в цифрах, назначение, курс, противопоказания, хранение. Всегда новые.

**Правила стилевого слоя:**

- Тон по аудитории: покупателю — тепло и просто, фармацевту — коротко, врачу — без эмпатии, медпреду — аргументированно.
- Тон по ситуации: беременность, дети, жалоба — бережно и с обязательной связкой к врачу; ловушка — нейтрально, без извинений.
- Не больше одной эмпатической фразы на ответ, факт раньше «воды», без восклицательных знаков в медицинских темах.
- Чувствительные ситуации — только фразы из утверждённой библиотеки.
- Запрещена эмпатия, которая звучит как обещание: «не переживайте, всё восстановится», «отличный выбор для вашей кожи».

**Ориентиры по объёму:** лекарство — 300–800 атомов (сложные препараты до 1000–1500), БАД — 60–100 атомов на продукт плюс ~40 атомов бренда, служебных ответов 20–40.

### 4. Плейбук: запуск бота по новому продукту

Пилот на первом продукте клиента занимает около 4 недель, дольше всего идёт согласование. Для каждого следующего продукта повторяются шаги 2–7, но только по дельте.

- **Квалификация продукта (день 1).**
  - Лекарство (рецептурное или безрецептурное), БАД, медизделие или косметика — от этого зависят источники и правила (раздел 6).
  - Какие аудитории нужны, какие каналы, кто согласует, сколько длится их цикл.
- **Сбор источников (дни 1–3).**
  - Лекарство: ОХЛП, инструкция, материалы медпредов, клинические данные для специалистов.
  - БАД: этикетка, СГР, материалы бренда, FAQ сайта.
  - Реальные вопросы: маркетплейсы, поддержка, горячая линия, вопросы от медпредов.
- **Черновик атомов (дни 3–5).**
  - Нейросеть раскладывает источники на атомы, мы размечаем уровни и аудитории.
  - Сверяем с уже утверждёнными атомами бренда и ингредиентов, помечаем только новые.
  - Цифры и дозы сверяем с источником вручную.
- **Согласование (неделя 2, зависит от клиента).**
  - Юристам уходит только дельта, новые атомы отдельно от утверждённых.
  - На первом клиенте туда же — стилевой слой, служебные ответы и стоп-лист.
  - Фиксируем версию и дату утверждения каждого атома.
- **Намерения и классификатор (неделя 3).**
  - Список намерений и формулировок вопросов по каждому, разметка по аудиториям.
  - Привязка намерений к атомам и правилам сборки.
- **Тестирование (неделя 3).**
  - Прогон тестового набора 200–300 вопросов (раздел 5), разбор ошибок, настройка порога.
  - Приёмка клиентом: демо на их вопросах.
- **Запуск в одном канале (неделя 4).**
  - Журнал с первого дня, ежедневный разбор нераспознанных вопросов в первые две недели.
- **Отчёт по пилоту.**
  - Доля отвеченных, доля служебных ответов, топ вопросов без ответа, список атомов на дозаведение.
  - Реальная кривая «новые атомы на продукт» — главный аргумент для раскатки.

### 5. Классификатор и качество

В «Контроле» классификатор — единственная «умная» часть, и главный риск: ошибка даёт согласованный, но чужой ответ. Например, взрослую дозировку на вопрос про ребёнка.

**Что классификатор должен определять:**

- аудиторию (или спросить её, если непонятно);
- одно или несколько намерений в одном вопросе («я беременна и пью Омегу» — два);
- жалобу на самочувствие (всегда раньше всего остального);
- вопрос не о продукте, провокацию, просьбу сравнить с конкурентом;
- уверенность по каждому намерению.

**Тестовый набор — 200–300 вопросов на продукт:**

- половина — обычные вопросы в разных формулировках, с ошибками и разговорной речью;
- половина — ловушки: сравнение с конкурентом, применение не по назначению, «а если удвоить дозу», дети, беременность, «это вылечит…», жалобы;
- по каждому вопросу — ожидаемые намерения и ожидаемый ответ (или служебная фраза);
- этот же набор — регрессионный тест при каждом изменении атомов.

**Метрики:**

| Метрика | Что показывает | Ориентир для запуска |
|---|---|---|
| Точность намерений на тестовом наборе | Как часто выбран правильный ответ | Уточнить на пилоте |
| Ошибки на ловушках | Опасные ответы | 0 |
| Доля служебных ответов в проде | Покрытие базы | Снижается неделя к неделе |
| Пропущенные жалобы | Нарушение процесса | 0 |

Порог уверенности настраиваем так, чтобы на ловушках не было ни одной ошибки, даже ценой лишних служебных ответов. Лишний «уточните вопрос» дешевле неправильного ответа.

### 6. Регуляторика

Правила зависят от типа продукта, поэтому тип определяем на первой встрече. Всё ниже — рабочие ориентиры, итоговые правила утверждают юристы клиента; мы не даём юридических заключений.

|  | Лекарство | БАД |
|---|---|---|
| Источник атомов | ОХЛП, инструкция | Этикетка, СГР, материалы бренда |
| Объём атомов | 300–800+ | 60–100 + атомы бренда |
| Главный риск ответа | Ошибка в дозах, особых группах, взаимодействиях | Обещание лечебного эффекта |
| Жалобы на самочувствие | Сообщение о нежелательной реакции: компания обязана его зарегистрировать (фармаконадзор) | Фиксируем и передаём в отдел качества |
| Покупателям | По рецептурным — ограничения на рекламу, бот фактически пересказывает инструкцию | Можно больше, но без лечебных формулировок |
| Обязательные пометки | По требованиям клиента | «БАД, не является лекарственным средством», рекомендация консультации с врачом |

**Правила для всех продуктов:**

- никаких «лечит», «излечивает», «гарантирует», «безопасно», «лучше, чем»;
- никаких сравнений с продуктами конкурентов;
- информация для специалистов не показывается покупателям — нужна проверка статуса в каналах для врачей и медпредов;
- каждое изменение атомов — через версию и повторное согласование; инструкции и этикетки обновляются.

**Персональные данные.** Вопросы вроде «я беременна» или «у меня аллергия» — данные о здоровье, особая категория по 152-ФЗ. Вероятно, клиент потребует хранение в России и российскую модель (GigaChat, YandexGPT). Выясняем на первой встрече, это влияет на архитектуру и цену.

### 7. Аудитории и каналы

Аудитории различаются глубиной, тоном и доступом; каналы — только способом доставки, база одна.

| Аудитория | Типичные вопросы | Тон | Доступ |
|---|---|---|---|
| Покупатель | Как принимать, можно ли при беременности, с другими средствами | Тепло, просто | Открытый |
| Фармацевт | Кому рекомендовать, чем отличается, хранение, срок годности | Коротко, для консультации у кассы | Открытый или по ссылке |
| Врач | Точные дозы, формы веществ, противопоказания, данные исследований | Точно, с цифрами | Проверка статуса |
| Медпредставитель | Ключевые сообщения, ответы на возражения | Аргументированно, в рамках согласованного | Внутренний |

| Канал | Для кого | Особенности |
|---|---|---|
| Виджет на сайте | Покупатели, фармацевты | Рядом с карточкой продукта |
| Telegram, MAX, VK | Покупатели | Можно добавить напоминания о курсе |
| Ozon, Wildberries | Покупатели | Черновики ответов в карточках, менеджер подтверждает; быстрый результат для брендов, живущих на маркетплейсах |
| Справочник для аптек | Фармацевты | Короткие ответы для консультации |
| Инструмент медпреда | Медпреды | Подготовка к визиту, отдельно или в их CRM |

На маркетплейсах клиент сравнит нас с автоответчиками за 390–25 000 ₽ в месяц. Этот канал продаём как «ответы, прошедшие юридический контроль», а не как автоответы.

### 8. Продажи

Первую встречу всегда строим на реальном продукте клиента: атомы с его этикетки и три диалога по ним убеждают сильнее любой схемы.

**Подготовка к встрече:**

- найти продукт, его этикетку или инструкцию, линейку бренда и каналы продаж;
- определить тип продукта (раздел 6);
- выписать 6–8 атомов и три диалога: обычный вопрос, вопрос специалиста, ловушка;
- посчитать уникальные формулы в линейке (фасовки 60/120 почти не добавляют атомов).

**Структура презентации (11 слайдов, есть готовый шаблон на Spice Active):** проблема → четыре аудитории → принцип атомов → атомы на их продукте → диалоги → как работает → правила регуляторики → каналы → план пилота → что нужно от клиента.

**Аргументы:**

- «Бот физически не может сказать ничего, чего вы не видели» — главный аргумент для юристов (линейка «Контроль»).
- «Юристы согласуют список фактов, а не сотни ответов, и по новым продуктам — только дельту».
- Масштабирование — как память переводов в переводческих агентствах: уже согласованный атом не согласуется повторно.
- Не обещать конкретный процент экономии на следующих продуктах, а обещать показать реальную кривую после трёх продуктов.

**Что запросить у клиента на встрече:**

- ☐ Источники: инструкции или этикетки, СГР, материалы медпредов и аптек, FAQ, выгрузка вопросов с маркетплейсов
- ☐ Приоритетный продукт и канал для пилота
- ☐ Контакт в юротделе и длительность их цикла согласования
- ☐ Требования к хранению данных (152-ФЗ, российская модель)
- ☐ Метрики успеха: нагрузка на поддержку, скорость ответа, конверсия

### 9. Ценообразование

Цена = фундамент + подключение продуктов + аудитории + каналы + абонплата. Платформа строится один раз на всех клиентов, поэтому первого клиента можно брать дешевле себестоимости ради кейса. Все цифры — наши оценки, а не чужой прайс.

**Абонплата включает:** хостинг, токены, мониторинг, ежемесячный отчёт о вопросах без ответа, пакет часов на обновление атомов. В «Живом диалоге» обязателен лимит диалогов: три вызова модели на сообщение стоят 1–3 ₽.

**Корпоративный уровень** (от 150–300 тыс. ₽/мес): SLA, выделенный контур, хранение в России.

**Логика для переговоров:** первый продукт дорогой, каждый следующий дешевле, потому что согласуется только дельта. Цена за продукт снижается по мере роста базы.

### 10. Эксплуатация после запуска

После запуска работа сводится к трём циклам: разбор журнала, обновление атомов, отчёт клиенту.

| Цикл | Частота | Что делаем | Кто |
|---|---|---|---|
| Разбор журнала | Ежедневно первые 2 недели, дальше еженедельно | Вопросы, ушедшие в служебный ответ; ошибки классификатора; жалобы | Мы |
| Дозаведение атомов | По накоплению, обычно раз в 2–4 недели | Черновик новых атомов → согласование дельты → прогон тестов → выкладка | Мы + юристы клиента |
| Обновление источников | При изменении инструкции, этикетки, состава | Находим затронутые атомы, помечаем устаревшими, пересогласуем | Мы по сигналу клиента |
| Регрессия | При любом изменении атомов или классификатора | Полный прогон тестового набора; ноль ошибок на ловушках — условие выкладки | Мы |
| Отчёт клиенту | Ежемесячно | Объём диалогов, доля отвеченных, топ вопросов, что добавили, что предлагаем | Мы |

Журнал — главный актив: он показывает, о чём реально спрашивают, даёт материал для новых атомов и аргументы для перехода с «Контроля» на «Живой диалог» и для раскатки на новые продукты.

| A12 | Продукт | Состав | Врач, фармацевт | В одной капсуле 100 мкг биотина — 200% от нормы потребления | Этикетка | Черновик |

**Промпт для черновика атомов:**

Разложи документ на атомарные утверждения. Одно утверждение — одна мысль, законченное предложение.
Цифры, дозы, противопоказания переноси буквально, без пересказа.
Для каждого укажи: раздел, уровень (бренд / ингредиент / продукт), аудитории, источник (раздел документа).
Ничего не добавляй от себя. Если формулировка неоднозначна — пометь «на проверку».

**Промпт генератора («Живой диалог»):**

Ты формулируешь ответ исключительно из переданных утверждений.
Можно менять порядок, связки и стиль под аудиторию.
Нельзя добавлять факты, цифры, сравнения и рекомендации, которых нет в утверждениях.
Если утверждений недостаточно — верни FALLBACK.
После каждого предложения укажи ID использованных утверждений.

**Промпт верификатора:** «Есть ли в тексте хоть одно фактическое утверждение, не выводимое из переданных утверждений? Ответь да/нет и процитируй его».

**Стартовый стоп-лист:** лечит, излечивает, вылечит, гарантирует, гарантированно, безопасно, без побочных эффектов, лучше чем, эффективнее, не переживайте, обязательно поможет, отличный выбор.

**Чек-лист готовности к запуску:**

- ☐ Атомы утверждены, у каждого версия и дата
- ☐ Стилевой слой, служебные ответы и стоп-лист утверждены
- ☐ Тестовый набор пройден, ноль ошибок на ловушках
- ☐ Жалобы уходят в отдел качества, адресат проверен
- ☐ Журнал пишется, доступ к нему у клиента есть
- ☐ Требования к хранению данных выполнены
- ☐ Клиент принял демо на своих вопросах

### 12. Риски и открытые вопросы

| Риск | Чем грозит | Что делаем |
|---|---|---|
| Ошибка классификатора | Согласованный, но чужой ответ | Порог уверенности, ловушки в тестах, служебный ответ при сомнении |
| Затяжное согласование у клиента | Срыв сроков пилота | Сроки пилота считаем от даты получения правок, фиксируем в договоре |
| Устаревшие атомы | Ответ по старой инструкции | Версии, обязанность клиента сообщать об изменениях, регрессия |
| Пропущенная жалоба | Для лекарств — нарушение фармаконадзора | Отдельный фильтр жалоб до классификатора, ноль пропусков в тестах |
| Механичное звучание в «Контроле» | Пользователи уходят | Стилевой слой, затем апгрейд до «Живого диалога» |
| Сравнение с дешёвыми автоответчиками | Давление на цену | Продаём юридический контроль, а не автоответы |
